# Product
<!-- impeccable:product-schema 1 -->

## Platform
web

## Summary
Akshat Porwal's evidence-first developer portfolio. It presents a small set of substantial projects, the technical decisions behind them, and verifiable GitHub work without inflated claims or generic portfolio filler.

## Audience
- Engineering recruiters and hiring managers evaluating technical depth.
- Developers considering collaboration or open-source work.
- Researchers and educators interested in AI learning systems.

## Primary visitor path
1. Understand what Akshat builds.
2. Scan the four strongest projects.
3. Open a project case study for contribution and implementation detail.
4. Verify recent work through GitHub activity and pull requests.
5. Continue the conversation through GitHub.

## Positioning
An editorial engineering portfolio: concise, inspectable, and grounded in shipped artifacts. The differentiator is the connection between AI research, learning products, and production-minded software engineering.

## Confirmed content
- Akshat studies a Bachelor of Software Engineering and Bachelor of Commerce (Actuarial Studies) at Monash University in Melbourne, from 2023 to 2027.
- Featured work: QuantumLearn, Velexar, Stonks in Hand, AI Engineering from Scratch, and Gradia.
- Public code and contribution evidence lives under `github.com/akshatporwal002` and the Monash FIT3170 team repository.
- No certification, impact metric, or employment claim should be published without a source.

## Experience principles
- Lead with proof, not adjectives.
- Keep the homepage concise; put depth in project pages.
- Make interaction feel tactile but never obscure navigation.
- Preserve useful behavior without JavaScript and under reduced motion.
- Meet WCAG AA contrast, focus, semantics, and target-size expectations.

## Technical constraints
- Next.js App Router, React, TypeScript, and Tailwind CSS.
- Server Components by default; isolate browser-only interactions in small Client Components.
- Static project data should generate project routes at build time.
- Public GitHub data must have a stable local fallback.
